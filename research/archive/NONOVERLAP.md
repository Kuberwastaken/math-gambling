# Separation of the twelve search workers

**For the current production geometry, completed tiles do not repeat the same `(D,r,z)` candidate position.** The ledger partitions generator indices exactly, and the arithmetic below rules out different surviving generators representing the same curve within a ratio band. A curve `(D,r)` can intentionally appear in different, disjoint z bands, so the reported number of curve checks is still not a count of distinct curves.

This conclusion is specific to the recorded box radii, plane radius, class multipliers, historical-frontier exclusion, and maximum ratio4096. It does not apply automatically to new sampling families, larger boxes, other campaigns, calibration repetitions, or retries of interrupted partial work. The current audit found no failure/recovery events and a maximum of one attempt per job.

`python3 verify_campaign_nonoverlap.py` checks the exact numerical inequalities, field/unit certificates, source hashes, band partition, permutation bijections and ledger reservations. Evidence is `runs/nonoverlap-certificate.json`. The mathematical argument is documented below; the script is not a formal proof of the entire C/Python implementation.

## 1. Exact ownership of inputs and quotient bands

Each context has a finite coefficient domain and a permutation whose stride is coprime to the domain size. Each index therefore identifies a different coefficient triple within that context. SQLite reserves disjoint index intervals before assigning workers; source-matched restarts preserve their cursors. Adjacent reserved index intervals are spread through coefficient space by the permutation, rather than representing neighboring chunks of coefficient coordinates.

The bands are `(0,64]`, `(64,256]`, and `(256,4096]` for `|z|/D`. The worker implements the lower endpoints strictly and upper endpoints inclusively using integer floor/ceiling operations. Thus a repeated generator in another band does different mathematical work. Existing direct-versus-split interval tests verify the endpoint implementation.

## 2. Different class multipliers cannot produce the same root ideal

Put `alpha³=114`, `gamma=a+b alpha+c alpha²`, `n=|Norm(gamma)|=ell D`, and `J=(5,alpha−4)`. The certified field computation gives `O_K=Z[alpha]`, class group of order3 generated by J, and `J²=(25,alpha−4)`. The workers use `ell=5^j`, `j=0,1,2`, and construct gamma in `J^j`.

For every surviving generated root, the worker has `gcd(C,D)=1`, with `C=b²−ac`. In fact `gcd(C,n)=1` also holds here. The only additional possible bad prime is5. If5 divides C and gamma belongs to J, then modulo5,

```
a=b−c,
C=b²−bc+c²=0.
```

The quadratic has discriminant−3=2, a nonsquare modulo5; hence a,b,c all vanish modulo5. This would make125 divide n. If5 does not divide D, however, `v_5(n)=j≤2`, a contradiction. If5 divides D, coprimality was already checked.

Write `A=a²−114bc` and `B=114c²−ab`. Exact identities give

```
B³−114C³ = Norm(gamma)(114c³−b³),
B²−AC = c Norm(gamma),
aC+bB+cA = 0.
```

Therefore `R=B/C mod n` satisfies `R³=114 mod n` and `gamma(R)=0 mod n`. The principal ideal `(gamma)` equals the root ideal `I(n,R)=(n,alpha−R)`, since inclusion and equal index n force equality.

The polynomial has a unique simple root modulo5, namely4, and its quadratic factor is irreducible. Unique Hensel lifting at5 and CRT elsewhere show

```
(gamma)=J^j I(D,r),
[I(D,r)]=[J]^(−j).
```

The three j values thus correspond to different ideal classes. Two different multipliers cannot emit the same `(D,r)`.

## 3. Unit bounds separate representations within a class

Two generators of the same principal ideal differ by a unit. PARI's certified unit group is generated by−1 and a fundamental unit whose positive inverse is

```
beta=4133238949+852423792 alpha+175800705 alpha².
```

Its norm is exactly1. `bnfisunit` returns fundamental exponent−1, and the roots-of-unity group has order2. In particular, `beta>4,133,238,949`. Absolute real embeddings of two generators of the same ideal have ratio `beta^m` for an integer m.

Every curve actually reached by the current frontier checker has

```
D ≥ floor(10^19/4096)+1 = 2,441,406,250,000,001.
```

For `D≤floor(10^19/54)`, this follows from `|z|>10^19` and `|z|≤4096D`; larger D automatically satisfy it.

Let r and w be the absolute real and complex embeddings of gamma. Then `n=r w²`. For box radius H, both embeddings are bounded by `B=31H+ell−1`, using `alpha<5`. For the plane family, exact rounding and certified rational approximations give `r<3ell` and `w<10^9`. Consequently:

| ell | Maximum real-embedding ratio within box | Within plane | Box/plane ratio, bounded below and above |
|---|---:|---:|---:|
| 1 | <1526 | <1229 | >338 and <635 million |
| 5 | <1526 | <1229 | >115 and <218 million |
| 25 | <1526 | <1229 | >39 and <75 million |

All upper bounds are below beta. Within either family, the only possible unit ratio is1, so the generators differ at most by sign. Between box and plane, the ratio is strictly between1 and beta, so no unit ratio is possible: the two families cannot represent the same ideal.

The exact bounds checked by the script are

```
within box: B³/(ell D_min) < beta_lower,
within plane: (3ell)(10^9)²/(ell D_min) < beta_lower,
box/plane: 1 < ell D_min/[B²(3ell)],
           B(10^9)²/(ell D_min) < beta_lower.
```

The unit ratio−1 in coefficient space is handled by the existing sign-symmetry rules: when both gamma and−gamma belong to a domain, exactly one survives. Asymmetric lattice boundaries are explicitly checked; an absent opposite is never assumed to have been searched.

## Consequence and limits

Together, the ledger, disjoint bands, class separation, unit bounds and sign handling eliminate duplicate `(D,r,z)` work within completed production tiles. This supplies a stronger justification than merely using different seeds. It does not enlarge the sampled domain, imply uniform sampling of ideals, establish an exhaustive height bound, or increase the predicted density of solutions.

The frozen worker's generic warning that curve checks can repeat remains appropriate: separate bands may share `(D,r)`, and the code supports configurations outside this proof. A future geometry must recheck these inequalities before claiming the same separation. Timeouts or crashes can also repeat partially executed work on recovery even though completed reservations remain disjoint.
